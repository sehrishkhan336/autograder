Detailed file map: see Section 7.

### 4.2 CI/CD Pipeline
Per the QA strategy in project instructions:
- GitHub Actions workflow on every push to main and PRs
- Required gates: `ruff check`, `pytest tests/unit`, `pytest tests/integration`, `pytest --cov --cov-fail-under=80`
- Nightly schedule for e2e tests (excluded from per-push to keep PRs fast)
- Failing checks block merge

### 4.3 Testing Pyramid Implementation
The QA strategy in project instructions is the authoritative spec. This kickoff does not restate it; treat that section as the contract.

Phase 3 implementation order:
1. Build the golden dataset (`tests/fixtures/golden/`) — 33 fixtures minimum
2. Wire test discovery to the new directory layout
3. Backfill unit tests to 80% coverage
4. Backfill integration tests covering router + agent loop + DB layer happy & error paths
5. Build e2e tests using golden dataset + email sandbox
6. Document bug triage protocol in CONTRIBUTING.md

### 4.4 Production Rollout
Test → production cutover is a staged process, not a flip.

| Stage | Duration | Activity | Exit gate |
|---|---|---|---|
| Soak | 1 week | Continue writing to TEST tables only; verify zero regressions on live volume | No new false rejects, no schema errors |
| Dual-write | 1 week | Write to TEST and PROD tables in parallel; compare nightly | Daily diff = empty |
| PROD-primary | 2 weeks | Write to PROD; TEST table archived weekly | Stable for 14 days |
| TEST-decommission | — | Drop TEST tables; archive shadow log | Ali sign-off |

### 4.5 Operational Maturity
- Runbook: `docs/RUNBOOK.md` — common failure modes and recovery steps
- Monitoring: nightly job emails a "yesterday's batch" digest to Ali
- Alerting: when agreement rate drops below baseline OR false rejects exceed zero, send Slack/email alert
- On-call: define who responds to alerts during business hours
